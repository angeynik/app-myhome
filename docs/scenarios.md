# Сценарии автоматизации

Сценарий управляет устройствами по условиям: значения датчиков и уставок, время суток, дни недели,
даты. Пример: «с 23:00 до 06:00 уставка котельной 16 °C, иначе 21 °C», «мощность насоса больше
1500 Вт полминуты — выключить насос и сообщить».

Сценарий — это **данные, а не код**. Пользователь создаёт и меняет его в приложении, сервер хранит
и проверяет, а **выполняет Node-RED** (вкладка «4. Сценарии», репозиторий `nRed`). Node-RED держит
копию сценариев в своём файле и работает без сервера и интернета.

> Этот файл одинаковый в репозиториях сервера и клиента (`docs/scenarios.md`). Поведение движка
> (вкладка «4. Сценарии») — `README.md` репозитория `nRed`, раздел 8. Меняете формат — обновляйте
> схему сервера (`services/scenarioStore.js`), движок (`functions/_scenario.js` в `nRed`), клиент
> (`src/utils/scenarioModel.js`) и обе копии этого файла.

## 1. Термины и файлы

| Термин | Что это |
|---|---|
| Сценарий | условие `when` + действия `then` (условие стало истинным) и `else` (стало ложным) |
| Точка | параметр устройства: `room` + `item` (`item_name` в `devices.json` и config-файле) |
| Переход | смена результата условия; действия выполняются только на переходах |
| Неизвестно | результат условия, когда у точки нет данных |

| Файл | Где | Кто пишет |
|---|---|---|
| `<DATA_DIR>/<dID>_scenarios.json` | сервер | `scenarioStore` по правкам из приложения |
| `scenarios.json` (`NR_SCENARIOS_FILE`, по умолчанию рядом с `devices.json`) | Node-RED | движок — копия последнего набора от сервера; пока сервер не присылал сценарии, можно править вручную |

## 2. Как работает

```
Vue post/scenarios ─▶ scenarioService.applyChange ─▶ <dID>_scenarios.json
                                       ├─▶ response/scenarios ─▶ все Vue dID с уровнем ≥ 2
                                       └─▶ post/scenarios ─────▶ Node-RED dID ─▶ scenarios.json
Node-RED init/init_ws ─▶ scenarioService.sendToNodeRED ─▶ post/scenarios (если файл есть)

Node-RED: значения MQTT ─┐
          таймер 5 с ────┼─▶ движок ─▶ команды «Команда → устройство» ─▶ MQTT
          ручные команды ┘          └▶ оповещения message/notify ─▶ сервер
```

- **Источник истины — сервер**, если у dID есть файл сценариев: Node-RED получает набор целиком
  при каждом подключении и после каждой правки. Нет файла на сервере — Node-RED работает по своему
  `scenarios.json`.
- **Вычисление.** При новом значении точки из условия и раз в 5 с (время, `forSec`, `stale`,
  задержки, повторы). Действия — только по переходу: стало истинным — `then`, ложным — `else`.
- **Трёхзначная логика.** Нет данных точки → «неизвестно». И: ложь, если есть ложь; иначе
  неизвестно, если есть неизвестное; иначе истина. ИЛИ — наоборот. НЕ от неизвестного —
  неизвестно, поэтому молчащий датчик не включает ветку «не». Пока результат неизвестен,
  состояние сценария не меняется (`onUnknown: "else"` — перейти в безопасное `else`).
- **Старт Node-RED.** Первое известное значение условия применяется (`onStart: "apply"`) без
  оповещений. Изменённые на сервере сценарии начинают заново, неизменённые сохраняют состояние.
- **Приоритет.** Точку, в которую записал сценарий, держит он, пока его состояние не сменилось;
  сценарий младшего приоритета в неё не пишет. Отпустил — младший сразу применяет своё состояние.
- **Ручное управление.** Команда из приложения или Telegram в точку сценария отключает сценарий
  для этой точки на `manualOverrideSec`; потом сценарий применяет своё текущее состояние.
- **Частота.** Не больше `maxCommandsPerMin` команд в одну точку за минуту; лишние пропускаются,
  пользователи получают одно оповещение.

## 3. Формат

### 3.1. Файл

```json
{
  "settings": { "tzOffsetMin": 180, "manualOverrideSec": 3600, "maxCommandsPerMin": 6 },
  "scenarios": { "<id>": { …сценарий… } }
}
```

| settings | По умолчанию | |
|---|---|---|
| `tzOffsetMin` | 180 | сдвиг местного времени от UTC в минутах (МСК), −840..840 |
| `manualOverrideSec` | 3600 | пауза сценариев после ручной команды, 0..604800 |
| `maxCommandsPerMin` | 6 | команд в одну точку за минуту, 1..60 |

### 3.2. Сценарий

| Поле | Тип | По умолчанию | |
|---|---|---|---|
| `id` | `^[A-Za-z0-9_-]{1,64}$` | — | ключ в `scenarios`, не меняется |
| `title` | строка 1..100 | — | |
| `description` | строка ≤ 500 | `""` | |
| `enabled` | boolean | `true` | |
| `mode` | `active` \| `test` | `active` | `test` — только журнал Node-RED, без команд и оповещений |
| `priority` | целое 0..100 | 50 | |
| `when` | условие (3.3) | — | |
| `then`, `else` | действия (3.4), до 20 | `[]` | хотя бы одно действие в сумме |
| `options.onUnknown` | `keep` \| `else` | `keep` | |
| `options.onStart` | `apply` \| `skip` | `apply` | |
| `options.minOnSec`, `minOffSec` | 0..604800 | 0 | минимальное время в состоянии |
| `options.repeatSec` | 0 или 30..604800 | 0 | повтор команд текущего состояния (без отложенных и оповещений) |
| `options.manualOverrideSec` | 0..604800 | из `settings` | 0 — ручное управление не учитывается (защиты) |
| `createdAt`, `updatedAt`, `updatedBy` | | | ставит сервер |

### 3.3. Условие

Каждый узел — **ровно один** вид. У любого узла может быть `forSec` (0..604800): истина
засчитывается, только если держится столько секунд подряд.

| Вид | Поля | Истина, когда |
|---|---|---|
| `all` | список 1..20 условий | все истинны |
| `any` | список 1..20 условий | хотя бы одно истинно |
| `not` | условие | вложенное ложно |
| `point` | `point: { room, item, request? }`, `op`, `value` \| `valueFrom`, `value2`, `hysteresis`, `sec` | см. ниже |
| `time` | `{ from: "ЧЧ:ММ", to: "ЧЧ:ММ" }`, `from ≠ to` | `from` ≤ время < `to`; `from > to` — через полночь |
| `days` | `[1..7]` | день недели: 1 — понедельник, 7 — воскресенье |
| `dates` | `{ from, to }`: оба `ГГГГ-ММ-ДД` или оба `ММ-ДД` | дата в диапазоне включительно; `ММ-ДД` — каждый год, через Новый год тоже |

`point`:

| `op` | Нужно | Истина, когда |
|---|---|---|
| `gt` `gte` `lt` `lte` `eq` `ne` | `value` (число, boolean, строка ≤ 64) или `valueFrom: { room, item, request?, offset? }` | сравнение выполнено |
| `between`, `outside` | числа `value` ≤ `value2` | значение внутри / вне `[value, value2]` |
| `stale` | `sec` > 0 | нет данных точки дольше `sec` (с момента старта Node-RED, если данных не было); никогда не «неизвестно» |

- `hysteresis` ≥ 0 — только для `gt`, `gte`, `lt`, `lte`: выполненное условие держится, пока
  значение не уйдёт за порог на `hysteresis` (`> 25` с гистерезисом 1 отпускает при `≤ 24`).
- boolean сравнивается как 1/0, строки — только `eq`/`ne`. Несравнимые типы — «неизвестно».
- Точка ищется в `devices.json` по `room` + `item` среди `sensors`, `system`, `setpoints`
  (`request` — если имя повторяется в разных разделах). Нет в `devices.json`, но имя на `s` —
  виртуальная уставка приложения: значение приходит командами из приложения (после старта
  Node-RED — неизвестно до первой команды). Иначе сценарий отключается с ошибкой.

### 3.4. Действия

| Действие | Поля |
|---|---|
| записать | `set: { room, item, request? }` + `value` \| `valueFrom: { room, item, request?, offset? }` |
| оповестить | `notify`: текст 1..1000, `severity`: `info` \| `ok` \| `warning` \| `alarm` (по умолчанию `info`), `level` 1..3 |
| любое | `delaySec` 0..604800 — выполнить через N секунд, если состояние сценария не сменилось |

- Записывать можно только в точку с `set` в `devices.json`; `min`/`max` проверяет
  «Команда → устройство» (вне диапазона — пропуск с предупреждением).
- Команда сценария уходит устройству напрямую и на сервер не пересылается; приложение увидит новое
  значение, когда устройство его подтвердит.
- Оповещения не отправляются при старте и при `repeatSec` — только на настоящем переходе.

## 4. Протокол WebSocket

| Направление | Сообщение | payload | Уровень |
|---|---|---|---|
| Vue → сервер | `get/scenarios` | `{}` | **2** |
| сервер → Vue | `response/scenarios` | файл (3.1); нет файла — `{ settings: по умолчанию, scenarios: {} }` | |
| Vue → сервер | `post/scenarios` | `{ action, configData }` | **2** |
| сервер → все Vue dID с уровнем ≥ 2 | `response/scenarios` | весь файл после каждой правки (включая автора) | |
| сервер → автор | `response/scenariosSuccess` | `{ action, id, delivered }` — `delivered`: сколько соединений Node-RED получили набор (0 — Node-RED не подключён, получит при подключении) | |
| сервер → автор | `error/scenariosError` | `{ message, code, action }` | |
| сервер → Node-RED | `post/scenarios` | весь файл (3.1) | |

| `action` | `configData` |
|---|---|
| `create` | сценарий (3.2) с `id`; id уже есть — `EXISTS` |
| `edit` | сценарий целиком с тем же `id`; нет — `NOT_FOUND` |
| `delete` | `{ id }` |
| `enable` | `{ id, enabled: true \| false }` |
| `settings` | `settings` (3.1) целиком |

Коды ошибок: `BAD_SCENARIO` (текст — что не так), `EXISTS`, `NOT_FOUND`, `LIMIT`, `BAD_ACTION`.

- `post/scenarios` не пересылается как есть (`NO_BROADCAST_POST`): после записи сервер сам
  рассылает итоговый файл.
- Сервер не знает точек `devices.json`: сценарий со ссылкой на несуществующую точку сервер примет,
  а Node-RED отключит его с предупреждением «сценарий id: … — отключён».

## 5. Сервер: устройство кода

| Модуль | Что делает |
|---|---|
| `services/scenarioStore.js` | схема Joi и смысловые проверки (`validateScenario`, `validateSettings`), файл `<dID>_scenarios.json`: `read`, `save` (`mustBeNew` / `mustExist`), `remove`, `setEnabled`, `saveSettings`; правки одного dID — строго по очереди |
| `services/scenarioService.js` | `applyChange` (правка → рассылка Vue уровня ≥ 2 → Node-RED), `sendToNodeRED` (при `init_ws`) |
| `services/messageHandlers.js` | `get/scenarios`, `post/scenarios` |
| `serverapp.js` | `init/init_ws` от Node-RED → `scenarioService.sendToNodeRED(dID)` |

## 6. Клиент: экраны и код

Меню шапки → **«Сценарии»** (пункт виден с уровня 2).

- **Список** (`/scenarios`, `ScenarioList.vue`): сценарии со старшим приоритетом сверху, у каждого —
  текст «Если … то … иначе …», метки «Тест» и «Защита» (приоритет ≥ 90), переключатель
  включения (`enable`). «+ Новый» — шаблоны. «Общие параметры» — `settings` (часовой пояс, пауза
  после ручного управления, команд в минуту).
- **Шаблоны** (`utils/scenarioTemplates.js`): уставка по расписанию, включение по времени, порог
  датчика, термостат, защита, датчик молчит, отпуск, с нуля. Шаблон подставляет подходящие точки
  конфигурации (датчик температуры и его пару-уставку по суффиксу, переключатель, датчик мощности…).
  Новый сценарий всегда в режиме «Тест».
- **Редактор** (`/scenarios/new?template=…`, `/scenarios/:id`, `ScenarioEditor.vue`): основное
  (название, включён, «Работает» / «Тест», приоритет: Обычный 50 / Важный 70 / Защита 90 или число),
  «Когда» — дерево условий, «Тогда» / «Иначе» — действия, «Надёжность» — `options`, «Итог» — текст
  сценария. «Сохранить» ждёт ответа сервера: ошибка — на экране, успех — к списку
  (`delivered: 0` — предупреждение, что Node-RED не подключён). Удаление — в два нажатия; уход с
  несохранёнными изменениями — с предупреждением.
- **Условие** (`ScenarioCondition.vue`, рекурсивный): группа «Все (И)» / «Любое (ИЛИ)», «+ Параметр»,
  «+ Время», «+ Дни», «+ Даты», «+ Группа»; у каждого узла «НЕ» (обёртка `{ not }`) и ✕. Параметр:
  сравнение (для ВКЛ/ВЫКЛ — только =, ≠, «нет данных»), значение или «с параметром» + сдвиг,
  диапазон, гистерезис, «держится не менее».
- **Код**: `store/modules/scenarios.js` (набор, `save` с ожиданием `scenariosSuccess` /
  `scenariosError`, правки по одной), `utils/scenarioModel.js` (точки конфигурации, черновик ↔
  сервер, проверка, текст), `ScenarioAction.vue`, `ScenarioPointSelect.vue`, `DurationInput.vue`.

## 7. Ограничения

| | Предел |
|---|---|
| сценариев на dID | 100 |
| вложенность условия | 6 уровней |
| узлов в условии | 50 |
| элементов в `all` / `any` | 20 |
| действий в `then` / `else` | 20 |
| секунд в любом поле `*Sec` | 604800 (7 суток) |

Восход и закат, условия по состоянию другого сценария и журнал выполнения в приложении пока не
реализованы.

## 8. Примеры

Полный пример под `devices.example.json` — `scenarios.example.json` в репозитории `nRed`.

Термостат с гистерезисом и без лета (И-НЕ):

```json
{
  "id": "pump_heat", "title": "Насос: подогрев", "priority": 40,
  "when": { "all": [
    { "point": { "room": "room02", "item": "dTemp02" }, "op": "lt",
      "valueFrom": { "room": "room02", "item": "sTemp02", "offset": -0.5 }, "hysteresis": 1 },
    { "not": { "dates": { "from": "05-15", "to": "09-15" } } }
  ] },
  "then": [{ "set": { "room": "room02", "item": "aPump01" }, "value": true }],
  "else": [{ "set": { "room": "room02", "item": "aPump01" }, "value": false }],
  "options": { "minOnSec": 300, "minOffSec": 300, "onUnknown": "else" }
}
```

Защита (ИЛИ, `forSec`, старший приоритет, ручное управление не учитывается):

```json
{
  "id": "pump_protect", "title": "Насос: защита", "priority": 90,
  "when": { "any": [
    { "point": { "room": "room02", "item": "dPower01" }, "op": "gt", "value": 1500, "forSec": 30 },
    { "point": { "room": "room02", "item": "dVoltage01" }, "op": "outside", "value": 190, "value2": 250, "forSec": 10 }
  ] },
  "then": [
    { "set": { "room": "room02", "item": "aPump01" }, "value": false },
    { "notify": "Насос отключён защитой", "severity": "alarm" }
  ],
  "options": { "minOnSec": 600, "repeatSec": 60, "manualOverrideSec": 0 }
}
```
